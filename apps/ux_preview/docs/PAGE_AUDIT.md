# BoMesh page audit

Each screen answers four questions: **what is it for**, **what is the main action**, **what does the user actually need to see**, and **what comes next**. The "Changed" column records what the HeroUI redesign added or removed against the previous prototype.

## Cross-product decisions

| Finding in the previous prototype | Decision |
| --- | --- |
| A custom visual system loosely inspired by HeroUI; components drifted per page | HeroUI v3 tokens (Theme Builder export) and HeroUI component anatomy/BEM names for every element; screens compose only `ui.js` builders |
| 6,000-line single script with monkey-patched layers | Core (state, router, builders, overlays, shell) + one isolated module per product area, loaded as ordered classic scripts so `file://` still works |
| Lifecycle rails, review notes, per-button `Preview` tags and explanatory paragraphs on most pages | Removed. Status chips + one alert carrying the fix replace rails; `Preview` is a single header chip on proposal-only pages |
| Inbox as a drawer, Connections hidden in a Sources tab, Documents only inside collections | Inbox is a first-class destination; accounts are Knowledge Studio → Sources → Accounts (Connections was a page in between, now a redirect); knowledge is found through the Knowledge Hub (below) |
| Review index as the landing page; page-audit side panel | Opening the prototype lands in the product (`/home`); review tooling is limited to the prototype bar |
| Accent/background/density theming options | One personal theme re-themes the whole app (HeroUI Theme Builder dimensions): 19 named themes (default BoMesh · Calm sage), accent swatches + custom hue, background tint (Base), radius, font, light/dark/system. Density stays removed; status and evidence colors stay fixed |
| Prototype bar overlapping the product | The bar owns a band below the product; overlays are contained by the app frame |
| Breakpoints based on the browser window | Container queries on the app frame, so the bar's tablet/phone previews exercise real rules |
| Uploads and syncs processed automatically in some flows | Aligned with `backend/docs_design`: syncs and uploads only change the inventory (Waiting); processing is explicit (Process); scheduled syncs sync then process |
| A knowledge chatbot can't help people finish the work that follows (decisions, reviews, paperwork) | Optional outcome modules — Spaces, Work, Requests — switched on per template or workspace, keeping one shell, one design system and one data model; code asks `hasModule()` rather than "is this workspace X?" |
| Workspace data was global; one demo company | Data is scoped per workspace behind the same `D` interface; personas belong to workspaces; the prototype bar switches workspace and persona |
| Answers ended the interaction | Answers carry next-step actions (start a request, draft a document, compare options, ask a space's staff); unanswerable questions become knowledge gaps and space questions whose answers become FAQ knowledge |
| Knowledge was a container drill-down (collection cards → document table) with a separate flat Documents list and search page | One Knowledge Hub with two destinations by intent: Browse (the organization's knowledge: one faceted catalog, URL state) · Saved · My files (personal sections, sidebar sub-rows under Knowledge), plus the Reader. Collections are managed in Manage › Knowledge Studio → Collections and are a Browse filter for readers. See [KNOWLEDGE_HUB.md](KNOWLEDGE_HUB.md) |
| Readers saw Waiting/Processing/Failed; nothing said whether a document could be trusted | Readers see trust (Verified, Review due, Not verified) and freshness; processing and publishing issues live in Manage › Knowledge Studio → Documents |
| Uploading put a file straight into a collection; anyone with edit rights effectively published it | Contribution, curation and publication are separate: Contribute → review (Manage › Knowledge Studio) → Approve & publish. Only published content reaches search, the Reader and the assistant. See [DOCUMENT_LIFECYCLE.md](DOCUMENT_LIFECYCLE.md) |
| Curation was scattered across collection inventories, Knowledge health and Sources; later one Documents page curated documents, but auto-published files were never classified and topics were matched by name only | One **Knowledge Studio** handles every origin (contributions, source syncs, uploads) in its sections Documents · Collections · Topics · Sources (sidebar sub-rows). Each document has two independent states, Publication and Processing state; processing (read → classify → index) runs only when someone asks. Classification runs against the workspace's topics (keywords, synonyms, rules and examples) and shows its evidence. |
| Platform admins had the same content access as workspace admins to see processing problems | Platform → Indexing shows job metadata only (ids, workspace, file type, step, error class) |
| Asking about a document left the document | The Reader keeps an Ask rail beside the document; answers cite passages that are marked in place on its Original; *Continue in chat* when needed |
| Realistic company records could be mistaken for real policy | Demo workspaces (`ws.demo`, e.g. Finx) carry a *Demo data* chip in the Knowledge header and the Reader |
| Enterprise opened on an empty chat; Knowledge opened on a separate landing tab; later Home opened on a large ask/find box that looked like the chat page | Home is where everyone starts: one Ask box with role starters, picks that say why, the domains; Getting started for new members. The knowledge map (an earlier Home) is Knowledge › Map; feeds and intent cards stay out. Knowledge opens on Browse. See [HOME.md](HOME.md) |
| Each page invented its own button weights, confirm rules and save model; rows carried Open/Review buttons beside a clickable row; ⋯ menus repeated visible actions | One action system ([DESIGN_SYSTEM.md](DESIGN_SYSTEM.md#rules)): one primary per region; alert and row buttons secondary sm; whole rows open their object with secondary actions revealed on hover/focus; ⋯ ≤ 8 grouped items; reversible changes instant with Undo, confirmation only for irreversible or high-risk actions; primaries stay enabled and validate on press; one vocabulary (Search documents / Ask AI, Contribute, Declined, Publish update, Everyone · Restricted · Private, Viewer · Editor · Owner, Evidence review, People) |
| Documents opened in a Browse drawer, a chat citation panel, work and request citation drawers, or straight in the Reader — four different previews | One **document preview** modal for every document row, card and citation: the document's Original with the cited passage marked (or a search's best match), ⋯ Ask about this document · Download, Open full document |
| A citation opened the native file and found its quote by searching the page text; where the rendering differed from the indexed text the quote was injected into the page to fake a highlight. Then a second rendering (Content View, the extracted blocks) beside the Original made a document look two ways | One rendering of a document: citations open its **Original** of the cited revision, the passage marked where indexing located it — `highlights`: boxes on a PDF page (fractions of the page, so they hold at every zoom), a cell range of a sheet, or the quote in a text view — never found by searching in the browser. A passage that can't be marked shows its quote card. The reading bar steps through the citations. Content View remains only for an assistant-made file's revisions |
| The sidebar mixed places with inline lists: a New chat row, a Projects tree with expandable conversations, Recent conversations with *All* → `/chats`; Manage collapsed to one row; the library carried Recent and Contributions tabs | One sidebar — Workspace (Home · Knowledge · New chat · Work · Requests), Your work (Projects · Spaces · My contributions), Manage, and last Recent: your conversations, as ChatGPT lists chats (a Recent page and an AI Chat list in between both repeated what this list does). Each row one responsibility
| Knowledge Studio's work was split into Review, Documents and Quality tabs, and Overview repeated their counts with its own shortcuts | One Review workbench with a queue chooser, a Documents registry, and Overview → Knowledge health linking each metric to its queue; master data became Taxonomy (tree + detail with a test box). Since superseded (next row) |
| Studio ran every document through one pipeline section whose stage bar mixed two axes (publication and processing), indexed everything before review, and used invented names for its queues; with 1,000+ uploaded documents an admin couldn't choose what to process | Sections named after their resources: **Documents** (views All · Review · Issues · Quality) and **Topics** (All · Suggestions), beside Collections · Sources. Upload doesn't mean processed: All filters by Processing state (Not processed · Processing · Processed · Failed · Outdated · Not supported; pills without counts), a selection (or "Select all matching", no number) goes through the Process dialog, and a processing strip shows progress with Stop. Review decides publication; its *Process it now* checkbox (on by default) is the explicit processing step, so approval never processes by itself (the earlier "index before review" decision is reversed). *Use my change to improve classification* sends corrections to Topics → Suggestions; topic changes re-check published documents without re-indexing. Overview → Knowledge health: Waiting for review · Issues · Not processed · Topic suggestions · Quality · Verified, each → its view; old addresses redirect. Since superseded (next row) |
| Reviewers decided on a classification guessed from a submission's title, then *Process it now* classified it again after publishing; failures (Issues) and quality checks (Quality) were two more tabs beside All and Review | **All · Processing · Review**, in the order work flows. A submission is processed before it's reviewed: Processing lists submissions first (then what nobody processed, failed or changed at the source) with **Process** as its primary; the assistant's classification moves the submission to Review, whose inspector says "Classified by the assistant when it was processed"; approval publishes only (no *Process it now*), and an approved new version waits Not processed in Processing. Issues folded into Processing (state pills Failed · Changed at the source); Quality became a filter in All (`quality=`) keeping each row's fix. Overview → Knowledge health: Processing · Review · Topic suggestions · Quality · Verified; `view=issues` and `view=quality&part=` redirect. See [KNOWLEDGE_STUDIO.md](KNOWLEDGE_STUDIO.md#documents) |
| People, Activity, Settings and platform Indexing split their sections with page tabs; the same verb varied (Create vs New for headers, Connect vs Add for sources, View vs Track in toasts) | An area's sections are sidebar sub-rows, each titled by its name; page tabs remain only for views of one thing (an entity, or one list's Mine/Shared views). One verb per action: **New X** opens a create dialog whose confirm is **Create …**; **Add source** everywhere; navigation toasts say **Open** |

## Verification

Checked in headless Chromium from `file://`:

- Every route for each persona renders without console errors, including forced Loading/Empty/Error states.
- Cross-module flows: Overview → Reconnect (then Knowledge Studio → Sources → Accounts) clears the alert and resumes sync; Inbox Approve updates requests and the badge; Knowledge → Ask starts a scoped conversation; palette navigation; every Journey starts on the right screen with the right dialog.
- Sync → Waiting → Process → Ready; upload → Waiting → Process now.
- Light and dark themes; 1440, 834 and 390 px widths (off-canvas sidebar, overlay panels, card rows, bottom-sheet dialogs).
- Home and the demo workspaces (Northwind, Finx personas, UTE Student · Lecturer · Admin): all routes with forced Empty/Loading/Error; the prototype journeys open the right screen; Home: starter fills the box, Ask opens the conversation, Getting started steps complete by doing them and hide with Undo, picks per persona with their reasons, domain and topic → filtered Browse; Knowledge map from Browse's header; product tour (Ask box, picks, domains, AI Chat, Search); role and workspace switching; 834 and 390 px without horizontal overflow; dark theme; Vietnamese; persistence with real `localStorage`; 0 console errors.
- Knowledge Hub (every persona): all Knowledge routes with forced Empty/Loading/Error; search → Browse → preview → Reader → in-place Ask with cited answers → Save → Saved; a lead links a resource to another space; saved items, views and recents survive a reload.
- Document lifecycle (Finx Engineer/Lead/Analyst/Admin, Northwind member/admin/operator): every Knowledge, Studio, Reader and Indexing route renders with forced Empty/Loading/Error; the engineer contributes with the dialog → Analyzing → Check the details → In review (absent from Browse) → the lead approves in Review → Publishing → Published → it appears in the engineer's Browse and Inbox; changes requested → revise → resubmit; new version is published as the original's next version (version increments); proposed topic accepted; duplicate compare and merge (references move to the kept document, Undo restores the duplicate only); bulk approve skips personal data; Undo restores; reviewers see only their collections; the indexing page contains no document titles; lifecycle changes survive a reload (real `localStorage`); review list/detail on a 390 px phone.
- Sidebar redesign (Finx admin/lead/analyst/engineer, Northwind member; desktop and phone, light and dark, EN and VI): group membership per persona; current row on `/chat`, `/chat/:id`, `/projects`, `/project/:id`, `/recent`, `/spaces`, `/space/:id`, `/doc/:id`, `/knowledge/library`, `/studio`, `/studio/collections/:id`, `/contributions`, `/work/:id`, `/overview` (Knowledge sub-rows Saved · My files and Knowledge Studio sub-rows current on their sections, a collection page marking Collections; no Studio sub-rows for the Finx engineer; the icon rail's section menus with Esc back to the rail button; ⌘K Go to finds sections; the bell shows pressed while the Inbox popover is open); collapse survives reload per person; the attention dot on a collapsed Your work; the top-row search icon only with the sidebar hidden; `/recent` filters and `/projects` create/delete with Undo; AI Chat list and `/chats` redirect; Contribute → Analyzing → Check the details → Open; Studio Review queues, bulk decisions with Undo, J/K, Documents filters, Knowledge health links and every legacy Studio address; Taxonomy edit/save/Undo, rules in the test box and import without the new columns; 0 console errors.
- Documents + Topics (explicit processing), checked in a headless browser for UTE admin, Finx admin, lead and analyst, and Northwind admin and member, with no console errors:
  - Documents views All · Processing · Review and their counts;
