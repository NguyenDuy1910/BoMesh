# BoMesh design system

HeroUI v3 is the only design authority. The prototype reproduces HeroUI's tokens, component anatomy and BEM class names in plain CSS so every element maps 1:1 to a documented component.

- Components: <https://heroui.com/en/docs/react/components>
- Theme: [Theme Builder — CRM, hue 139.21, base 0.02, Google Sans, radius M, field radius L](https://heroui.com/en/themes?template=crm&hue=139.20631987695046&fontFamily=google-sans&base=0.02)
- Living gallery: `ux-preview.html#/design` (rendered with the same builders as the product, so it cannot drift).

## Tokens — `styles/tokens.css`

Light and dark lightness values are the Theme Builder export; hover, soft and border variants use HeroUI's own `color-mix()` formulas from `themes/default/variables.css`. Components and pages use only these variables.

**Themes change the whole interface.** Appearance is a personal setting with the Theme Builder's dimensions, and every one of them re-themes all screens at once:

| Dimension | Options | What it drives |
| --- | --- | --- |
| Mode | Light, Dark, System | `<html data-theme>` |
| Theme | 20 named looks: **Ink (default: graphite accent on a softly tinted neutral canvas, medium radius, Be Vietnam Pro, light mode)**, BoMesh (calm sage), Fresh green (the original CRM export), HeroUI, Ocean, Sky, Forest, Lagoon, Midnight, Lavender, Plum, Orchid, Sakura, Rose, Crimson, Sunset, Amber, Lemon, Lime, Graphite | Bundles the four settings below; changing any of them makes the theme "Custom". The default applies only to people who never chose a look; a stored choice (this device or the account) always wins. A stored BoMesh look always follows the current BoMesh definition |
| Accent | 19 swatches (sage, green → graphite) + custom hue slider | `--accent`, `--accent-foreground`, `--focus`, accent soft tones: primary buttons, links, current navigation icon, selection, focus rings, charts |
| Background tint (Theme Builder "Base") | Neutral 0, Subtle 0.5×, Tinted 1× (export), Rich 1.8× | Every neutral — canvas, surfaces, fields, borders, text — at the accent hue |
| Radius | None, Small, Medium (export), Large, XL | `--radius` scale; fields get 1.5× |
| Font | Google Sans (export), Inter, Be Vietnam Pro, IBM Plex Sans, Manrope, System | `--font-sans`; Google fonts load on demand, system fallback offline |

Mechanics: `scripts/core/theme.js` holds the registries (`ACCENTS`, `BASES`, `RADII`, `FONTS`, `THEMES`) and `applyTheme()`, which writes the inputs (`--accent-l/c/h`, `--accent-fg`, `--accent-ink`, `--base-hue`, `--tint`, `--radius`, `--field-radius`, `--font-sans`) on `<html>`. `tokens.css` derives every color from them; its `:root` defaults are the BoMesh theme. Light accents (Amber, Yellow, Lime) use dark text on the accent and a darker soft foreground; Graphite flips to near-white in dark mode. Status (success, warning, danger) and evidence colors never change: they carry meaning, not brand. Workspace marks keep the workspace's own logo color. The look is persisted with the mode (`S.look`). Add a theme by adding a `THEMES` entry; add an accent in `ACCENTS`.

UI: the **Appearance** drawer (`features/appearance.js`, clear backdrop so the app re-themes live behind it) shows mode (Light · Dark · System), a gallery of theme cards (each drawn from its own colors via `themePreview()`), then Customize: accent (ColorSwatchPicker + hue slider), background tint, radius and font. Entry points: account menu (Appearance, with the current mode · theme), Preferences (Appearance row), command palette ("Switch to dark/light mode"), prototype bar (Mode + quick themes and "Theme and colors…", with Undo toast) and `#/design`.

| Role | Tokens | Use |
| --- | --- | --- |
| Canvas | `--background`, `--foreground`, `--muted` | App background, body text, secondary text (tinted at the accent hue by the background tint) |
| Surfaces | `--surface`, `--surface-secondary`, `--surface-tertiary`, `--overlay` | Cards/lists/table bodies; table roots and quiet panels; skeletons; menus, dialogs, drawers, toasts |
| Controls | `--default`, `--default-hover`, `--field-background`, `--segment` | Tertiary buttons, chips, switch tracks; inputs; selected tab/segment |
| Accent | `--accent`, `--accent-soft`, `--accent-soft-foreground`, `--focus` | Primary action, current navigation, selection, focus ring |
| Status | `--success`, `--warning`, `--danger` (+ `-soft`, `-soft-foreground`) | Status chips, alerts, destructive actions |
| Category tones | `--tone-blue`, `--tone-violet`, `--tone-teal`, `--tone-amber`, `--tone-pink`, `--tone-green`; classes `tone-*`; `CATEGORY_TONES`, `categoryTone(key)`; `categoryColor(key)` | Identity colors for kinds, never for status. The six tones serve small sets a reader scans by (permission groups, roles). Topic domains are too many for six: each uses its stored color — picked from `DOMAIN_COLORS` (`core/ui.js`, web `src/lib/tones.ts`: twelve mid-tone hues, no status red; a new domain gets `freeDomainColor`, the first one no domain uses; swatches are `swatchPicker({ size: 'sm' })`) — else `categoryColor` — a hue hashed from its ID, skipping the red band status owns, at the same lightness and chroma — passed inline as `--tone`. Rendered only as a soft tile, tag or mark with ink; never as text color or a large fill |
| Lines | `--border`, `--separator` | Outline buttons, dividers, table rows |
| Elevation | `--surface-shadow`, `--lift-shadow`, `--overlay-shadow`, `--field-shadow`, `--button-shadow`, `--card-border`, `--field-border`, `--focus-halo` | Calm elevation: every surface is a hairline (`--card-border`, `--field-border`) plus a low, soft shadow; clickable cards lift on hover (`--lift-shadow`); primary buttons carry a soft shadow; focused fields get an accent edge and a soft halo. Dark mode uses borders instead of shadows |
| Evidence | `--evidence`, `--evidence-strong` | Citation markers, cited quotes and the citations marked on a document's Original — boxes over PDF pages (`.doc-hl`), tinted grid cells, the quote in a text view (`--evidence-strong` for the citation in focus; derived from warning; never reused for generic warnings) |
| Highlight | `--highlight`, `--highlight-foreground` | Search-term matches in titles, snippets and the viewer (soft accent wash) |
| Type | `--text-2xs` … `--text-3xl` with `--leading-*` (11/14, 12/16, 13/19, 14/21, 16/24, 18/26, 22/30, 28/36) | Every font size and line height; weights 400/500/600 only |
| Spacing | `--space-1` … `--space-14` (4 px scale: 4, 8, 12, 16, 20, 24, 32, 40, 48, 56) | Gaps, paddings, page/section rhythm (32/40 px) |
| Controls | `--control-sm` 32, `--control-md` 36, `--control-lg` 44, `--touch-min` | Button/field heights; touch targets ≥ 40 px on coarse pointers |

Radius scale is HeroUI's (`--radius` = 8 px in the default theme): fields 12 px, cards/lists/table bodies 16 px, dialogs/drawers/toasts 24 px, buttons/chips/tabs pill. The theme's radius setting scales all of these.

Typography: Be Vietnam Pro in the default Ink theme (Google Sans Flex in the themes that pick it; system fallback offline); the theme's font replaces `--font-sans` everywhere. Body 14/21, labels 13/19 medium, meta 12/16, card title 15/22 semibold, section 16/24 semibold, dialog/drawer title 18/26 semibold, page title 22/30 semibold (−1.5 % tracking), display 28/36, KPI 24/32 semibold tabular. Weights are 400/500/600. Headings tighten tracking slightly; body text never does. Hierarchy comes from size, weight and color together: a group or section heading is never smaller or lighter than the rows it heads.

Calm defaults: near-white canvas with white surfaces, hairlines instead of heavy borders, one accent used sparingly (primary action, current-page icon, selection, focus), neutral current-page highlight in the sidebar (neutral tint, medium weight, accent icon), no gray slabs behind content and no cards nested inside cards. Card padding 20 px; tabs sit on a hairline separator. Calm is not monochrome: where people scan categories (groups, roles, kinds) each category carries its own tone tile, and yes/no answers are ticks, so structure reads from color as well as from text.

## Components — `styles/components.css` + `scripts/core/ui.js`

Screens never hand-roll markup for these; they call the builder.

| HeroUI component | Builder | Notes |
| --- | --- | --- |
| Button | `btn(label, {v, size, icon, loading, menu, href})`, `iconBtn`, `linkBtn` | Variants `primary` (one per region, soft shadow), `secondary` (outlined white surface, dark text, accent icon), `tertiary` (soft gray, default), `ghost` (text; Cancel in dialogs), `outline`, `link` (`linkBtn`: quiet text action, icon after the label), `danger`, `danger-soft`; sizes sm 32 / md 36 / lg 44; press scales to 0.97; loading keeps width. Buttons inside alerts and list rows pass through `quietActions()`: primary/tertiary become `secondary`, every size becomes `sm` |
| Chip | `chip(label, {tone, variant})`, `status(kind, value)` | One status vocabulary (`STATUS` in ui.js). Healthy steady states are quiet (tertiary); action-required states are soft color + dot |
| Badge | `badge(n, {tone, label, dot})` | Count with one meaning per tone: `danger` = something is broken, `accent` = needs you, `default` = information. Renders nothing for 0; `dot` replaces the number (a collapsed sidebar group whose rows need you). A badge counts exactly what its landing view shows |
| Card | `card()`, `statCard()` | Hairline + soft shadow; `card--action` lifts 1 px with `--lift-shadow` on hover. KPI card follows the CRM template: icon tile, label, value, meta |
| ListBox | `list()`, `item({act, href, trail, lines})` | Rows with lead icon/avatar, title, description, meta, trailing actions. With `act`/`href` the title is the real button/link stretched over the row, so trailing actions stay sibling controls (never nested). `lines: 2` lets the title wrap on phones (messages, notifications). Secondary trailing actions use `.reveal-on-hover`; `.item__trail` wraps under the content below 680 px |
| Table | `table()`, `sortHead`, `selCheck`, `selectionBar`, `pager` | HeroUI primary table (gray root, white body). `pager` renders only when there's more than one page. Selecting rows swaps the toolbar for `selectionBar` in the same place, right above the rows (count · actions · Clear selection; icons only on phones) — the pattern of Carbon's batch actions and Gmail/GitHub lists. People → Members uses it; the other lists still render the floating `bulkBar` and move to `selectionBar` next. Below 760 px rows become cards (primary cell, actions, wrapped metadata) |
| Tick | `tick(on, {yes, no})` | Yes/no cell of a comparison table (a matrix of permissions, plans or features): yes is a soft-success disc with a bold check, no is a quiet dash — never an empty cell. Centred under its column; the answer is spoken to screen readers |
| Topic tag | `topicTag(id, {href})`, `topicLook(id)` (`core/catalog.js`; web `TopicTag`, `topicToneProps`) | A document's topic as a soft chip in its domain's color with its icon (the topic's own, else its domain's, else a tag; a domain's falls back to layers) — people pick icons only from `TOPIC_ICONS` (`core/catalog.js`; web `TOPIC_ICONS` in `modules/home/domainIcon.ts`, same names, each in the sprite and the Lucide registry), so a domain's topics read as one family. A link in rows and Details; plain inside a card (the whole card is the control) and in Studio's Documents table, where only the first shows with +n. The same look carries every place a document's topics are chosen: Review's suggestion chips (chosen = the tag with a small check, declined = a dashed outline with +) and the `topicPicker` chips of Contribute and Process (quiet pickers, a setting rather than the document's metadata, stay neutral). Browse's topic pills lead with the same icon and take that color's soft wash when chosen |
| Tabs | `tabs(items, active, base, {variant, act})` | `secondary` (underline) for page sections, `primary` (pill) for in-content filters; tabs are links so sections are deep-linkable. With `act` they are toggle buttons (`aria-pressed`) for in-content filtering. An item `{ sep: true }` draws a group divider. Narrow containers scroll the tabs with an edge fade and keep the current tab in view. Sections of Knowledge and Knowledge Studio are sidebar sub-rows, not tabs |
| ToggleButtonGroup | `seg({iconOnly})` | Mutually exclusive view options; `iconOnly` shows icons with the label as accessible name and tooltip |
| TextField / TextArea / Select | `field()` + `input()` / `textarea()` / `select()` | Visible label, description, inline `FieldError` with `aria-invalid` |
| Click-to-edit title | `editableTitle({ id, value, editing, edit, commit, cancel, tag, cls, label, maxlength, error, data, headingId })` (`core/ui.js`, `.etitle*` in `components.css`); hosts: `pageHeader({ heading })` (entity hero H1, or the top row's H1 on index pages), drawers and dialogs `titleEdit: {…}` in place of `title` | The name of an entity is its own rename control, for people who may rename it (plain text for others): at rest the text with a quiet pencil (full strength on hover/focus); pressing it swaps in an input of the same size. Enter or leaving the field saves (`data-blur`, deferred past the click that caused it so that click still lands; a re-render's blur is ignored), Escape cancels (before any dialog's Escape), an error keeps it open under the field. Focus follows the button ⇄ input swap. In the top row it stays one line and truncates. Applies at once with Undo — never a ⋯ → Rename item or a rename dialog where the name heads a page, panel or drawer (a list row that is one link, e.g. AI Chat's conversations or Projects, keeps ⋯ Rename… in a small dialog). `commit` must be idempotent |
| Switch / Checkbox / RadioGroup | `switchCtl`, `switchRow`, `checkbox`, `choiceGroup` | Radio cards for consequential choices; options `[value, title, desc, icon]` — with an icon the card leads with a tinted icon tile instead of the dot, and 3+ columns render as tiles |
| Slider | `slider({ id, value, min, max, step, input, change, label, valueText, ends })` + `setSlider(el, valueText)` (`core/ui.js`, `.slider*` in `components.css`) | HeroUI Slider: label and value on one row, a 6 px track (`--default`, dark `--surface-tertiary`) filled with `--accent` up to `--fill`, a white 20 px thumb with the theme focus ring, optional end labels. `input` fires while dragging; update in place with `setSlider` (no re-render) |
| Disclosure | `disclosure({ path, title, summary, icon, body })` | Progressive disclosure for optional or advanced settings and long pickers; the collapsed row shows the current choice (`summary`); state at `S.ui[path]`, toggled by `ui-toggle` |
| Option list | `<div class="option-list">` around `checkbox()` rows | Bordered, scrollable picker (max 220 px) with roomy hover rows; never more than a handful of bare checkboxes in a dialog |
| SearchField | `searchField({uiKey, bind, act, value, placeholder, id, size, autofocus, label, full, enter})`, `needsTools(n, uiKey, fields)` | The one search input. `uiKey` filters `S.ui[uiKey].q`; `bind`/`act` make it work in dialogs and pickers; a clear (×) button whenever non-empty, Escape clears. Sizes sm (toolbars) / md (dialogs) / lg (page search). Search, sort, filters and bulk selection render only when `needsTools` says the list needs them (7+ items, `TOOLS_MIN`) or one is in use |
| Popover | `PO[name](trigger) → { title, body, foot, width }`, trigger `data-popover="name"` + `aria-haspopup="dialog"` | Inline filters, small pickers and the Inbox (`PO.inbox`, 400 px wide, max 600 px tall, under the top-row bell). Stays open while you interact (checkboxes call `refreshLayer()`), closes on outside click/Esc and returns focus to the trigger. Below 680 px it renders as a bottom sheet with a Done button |
| Alert | `alertBox(tone, title, desc, actions)` | One alert per problem, with its fix as the action |
| EmptyState | `emptyState()`, `errorState()` | First use, no results, no access and failure have different copy and recovery |
| Skeleton / ProgressBar / Spinner | `skelRows`, `skelCards`, `progress`, `spinner` | Structure-preserving loading |
| Avatar / Kbd | `avatar(name, size)`, `kbd()` (web `UserAvatar`) | An avatar is a soft tile of a category tone with ink (`avatar--tone tone-*`, the `categoryTone(name)` hash), stable per name and never a status color, so no one's initials read as an error. The system actor (BoMesh) is a neutral `avatar--default` with a bolt |
| Modal / Drawer / Dropdown / Toast / Tooltip | `M`, `DR`, `MENUS`, `toast()`, `data-tip` (overlays.js) | Modal: `{ title, icon, tone, desc, body, footStart, foot, size, after }` — a 40 px tinted icon tile names the action, `desc` says what happens next (aria-describedby), the footer is a quiet band with an optional hint on the left (`footStart`), ghost Cancel and a primary that repeats the title's verb; `after(dialogEl)` runs once the dialog is in the DOM. `confirmAction` adds an alert/help tile and keeps its primary enabled, validating on press. Sizes sm · md · lg · xl · `preview`. Backdrop blurs lightly. Modal becomes a bottom sheet and drawer a full-height sheet below 680 px. Dropdown (⋯) menus group items with `{ section }` headings, ≤ 8 items, destructive last after a separator; `data-menu-side="right"` opens a menu to the trigger's right (the icon rail's section menu `MENUS['nav-sub']`). Toasts live in a persistent `#toasts` live region: compact (40 px, 13 px text, max 360 px) in the bottom-right corner, full width at the bottom on phones, above the composer on chat threads; Undo toasts stay 8 s and pause on hover/focus. Tooltips only via `data-tip` (never native `title`) |
| Breadcrumbs | `crumbs([...])` | The parent trail inside the CompactHeader's top row (quiet links with chevrons, no separate row); phones show only a Back icon to the nearest parent |

Domain marks: `fileIcon(type)` (soft tone per file family), `appIcon(key)` (connector brand glyph on a neutral tile), `wsMark(ws)`, `X.spaceMark(space)` (space color tile with the space-type icon), sidebar `.space-dot`, and `.cite` citation markers.

Text helpers: `isQuestion(q)` (does typed text read like a question — decides whether Ask AI or Search documents ranks first) and `bareName(n)` / `X.docTitle(doc)` (a document's display title without its file extension, used everywhere).

- Rows are `navItem()` (`id="nav-<id>"`, icon, label, optional badge); groups are `navGroup()` (`.sidebar__group`, label as a toggle button with chevron). The sidebar lists conversations only in its Recent group, never projects.

- **Sub-rows:** an area's sections are always sidebar sub-rows, never page tabs. While you're in the area and the sidebar is expanded (also off-canvas), its row shows its sections as indented sub-rows — Knowledge: Saved · My files (`X.res.libraryNav()`); Knowledge Studio: Documents · Collections · Topics · Sources, only the ones the caller may use (`X.studioNav()`; `/studio/collections/:id` marks Collections); People: Members · Groups · Roles · Access requests; Activity: Changes · Sign-ins; Settings: General · Workspace setup; platform console Indexing: By workspace · Jobs · Policies. Rendered only with ≥ 2 sections (`navKids`). - Your work shows My contributions to anyone who can contribute or has submissions; Manage appears only with a manage permission (collection owners and editors get Knowledge Studio).
- **Collapse:** Your work and Manage collapse; open by default; stored per person (`D.navGroups[userId]`), so it survives reload and differs between people. A group stays open while you're on one of its pages. A collapsed group shows a `dot` badge when a row inside needs you.

The variant sets `--page-max`, shared by the top row. Widths are tokens (`--layout-form`, `--layout-centered`, `--layout-conversation`).

## Rules

These implement the product principles in [PRODUCT_DESIGN_RULES.md](../PRODUCT_DESIGN_RULES.md) (binding for every page and component).

1. **One primary per region** (the page's actions in the top row, dialog footer, drawer footer, card); everything else is secondary, tertiary, ghost or in a menu. Buttons inside alerts and list rows are `secondary` size `sm` (decisions: Approve = secondary, Decline = ghost). Destructive = `danger-soft`.
2. **Rows**: the whole row or card is the click target and opens the object; it never also carries an Open/View/Review button. Secondary row actions (Save, ⋯, remove) use `.reveal-on-hover` — shown on hover/focus-within, always visible on touch (`@media (hover: none)`); a set state (a saved bookmark) stays visible.
3. **⋯ menus** never repeat an action visible on the same surface; ≤ 8 items; grouped with `{ section }` headings (reading · Use in · editor/admin); destructive last after a separator.
4. **Save model**: state flips, membership and toggles apply immediately; a person's role is chosen in the role dialog (every role with its description) and applies on its confirm; multi-field text forms use a savebar (Save / Discard) or dialog Save / Cancel, and Cancel truly discards. Never both in one surface. All of these carry Undo where reversible; the classification and the save bar's own feedback: [feedback-design-system.md §5, §10](feedback-design-system.md#5-destructive-actions-undo-and-confirmation).
5. **Confirmations** only for irreversible or high-risk actions; reversible actions act immediately with Undo. The classification, examples and dialog behavior live in [feedback-design-system.md §5](feedback-design-system.md#5-destructive-actions-undo-and-confirmation).
6. **Enabled primaries**: primaries stay enabled and explain what's missing on press (inline FieldError / helper text). Disabled only when permission-blocked, with a `data-tip` saying why. Hide what the caller cannot do.
7. **Every status has a next step** visible to the person responsible; no dead ends.
8. **Never fake success** ([feedback-design-system.md §1](feedback-design-system.md#1-principles)): every action changes coherent mock state and the UI reflects it; prototype-only simulations carry a Demo data / `Preview` chip (platform console, workspace archive).
9. Status is never color alone (chip label + dot/icon). No decorative gradients, illustrations or metric walls; numbers appear only where they lead to an action, and every count appears once.
10. Dialogs follow one pattern: icon tile + verb-first title + one-line description of what happens next; fields grouped top-down with smart defaults and inline validation that clears as you type; advanced or long options behind a `disclosure`; a quiet footer hint (`footStart`), ghost Cancel and a primary that repeats the verb, shows `loading`, and ends in the feedback [feedback-design-system.md §3](feedback-design-system.md#3-decision-framework) assigns (often none: the result is visible).
11. Progressive disclosure by default ([PRODUCT_DESIGN_RULES.md](../PRODUCT_DESIGN_RULES.md)): tools appear when the content needs them (list tools at 7+ items, pagination at 2+ pages, tabs only when they split something), side panels open on demand and one at a time, sidebar groups (Your work, Manage) start open and collapse on request, remembered per person; a collapsed group shows a dot when something inside needs you, and the group holding the current page stays open.

## Responsive

Breakpoints are container queries on `#frame` (`@container app`), so the prototype's tablet (834 px) and phone (390 px) previews exercise the real rules.

| Width | Behavior |
| --- | --- |
| ≥ 1024 px | Persistent sidebar (collapses to the 56 px icon rail from its header toggle or ⌘\; search stays in the sidebar/rail), side panels inline |
| < 1024 px | Sidebar off-canvas with backdrop, opened from the top row's menu button (a row navigates and closes it; top-row Search icon); side panels overlay; form sections stack |
| < 760 px | Tables become card rows |
| < 680 px | 16 px gutters, compact headers, trailing actions and toolbars wrap under content, modals and popovers as bottom sheets, drawers as full-height sheets, single-column grids, no keyboard-only hints on touch |

## Accessibility

Landmarks and headings; visible 2 px accent focus ring with offset; labels on every control; `aria-current`, `aria-selected`, `aria-checked`, `aria-expanded`, `aria-invalid`, live toast region; focus trapped in dialogs and returned to the trigger; full keyboard support for menus (arrows/Home/End/Escape), palette, tabs and actionable rows; reduced-motion respected; status never conveyed by color alone.

## Language

The interface is **Vietnamese only** for now (no language switch; a later phase designs multilingual support); **content keeps the language it was written in**.
