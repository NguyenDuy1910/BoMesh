# Knowledge Hub

The Knowledge Hub replaces the old *Collection → Documents* drill-down. People find, read and use knowledge, whatever system it came from. It is a platform capability: Finx Workspace is the main demo ([FINX_WORKSPACE.md](FINX_WORKSPACE.md)), and Northwind runs the same code. Discovery starts on **Home** ([HOME.md](HOME.md)). The Knowledge section has two destinations, one per intent: **Browse** (find and read the organization's knowledge) and the personal sections **Saved · My files** (what I kept and uploaded), shown as sidebar sub-rows under Knowledge; there is no tab bar. What you touched lately and what you submitted are **Your work → Recent** and **Your work → My contributions** in the sidebar ([PRODUCT_FLOW.md](PRODUCT_FLOW.md#information-architecture)). Collections are an administrative concept: their owners and editors manage them in **Manage › Knowledge Studio → Collections**; readers meet a collection only as a Browse filter.

```text
Sources ──► one Resource catalog ──► Home · Browse · Saved ──► Preview ──► Reader ──► Ask · Save · Collect · Use in work
              (permission-filtered)       (many views, no copies)                  (provenance, trust, related)
```

## What was wrong

| Before | Problem | Now |
| --- | --- | --- |
| Knowledge = a grid of collection cards; documents only inside a collection | People had to know which container held something. There was no way to find by topic, type, space, owner, source or freshness. | **Browse** is one catalog filtered by nine dimensions, and the URL holds the state. A resource shows up in every view without being copied. |
| A flat document list, `/search` and the collection tables were three overlapping finders | Duplicated capability with inconsistent results | Browse is the only knowledge finder. The old list's address now redirects to the reviewers' **Knowledge Studio** (Manage › Knowledge Studio). Global search and ⌘K both use the same catalog search. |
| Readers saw Waiting, Processing and Failed | Pipeline states mean nothing to readers and make the product look broken | Readers see **trust**: Verified, Review due or Not verified, plus freshness. Only the collection's editors see index status. |
| The viewer showed a page and a metadata panel; *Ask* left for chat | Reading context was lost. There was no provenance, version history or related material. | The **Reader** has Ask, About and Related beside the document. Answers cite blocks of the document, highlighted in place in Content View. |
| Nothing personal | People couldn't keep what they found | **Saved** and **My files** (recent reads → Your work → Recent; contributions → My contributions) |
| Browse · library · Collections as three tabs | *Collections* exposed the access boundary as a place to read: a collection's Resources tab repeated Browse filtered by collection, its list repeated the Browse filter, and access, sources and settings sat beside reading. Continue reading repeated the old recent-reads tab, *Only documents I saved* repeated Saved, and saved views were listed in both Browse and the library. | Browse plus personal sections (sidebar sub-rows). A collection is a Browse filter (`kb=`); a filter on a locked collection offers Request access, and *Some collections aren't shared with you* opens the restricted collections. Collection management (access, sources, settings, create) moved to Manage › Knowledge Studio → Collections ([KNOWLEDGE_STUDIO.md](KNOWLEDGE_STUDIO.md)). Saved views live only in Browse's Views menu (open, save, rename, delete). |
| No governance | Stale policies, untagged files and duplicates were invisible | **Manage › Knowledge Studio** sets up knowledge (collections, topics, sources) and runs every document in **Documents**: All (every document, filterable by Processing state, and a Quality filter for re-verification, missing details and duplicates), Processing (what isn't processed yet: submissions first, then what nobody processed, failed or changed at the source; select and Process, since nothing is processed on upload) and Review (processed submissions, new versions and what a sync held back; approving publishes only). **Topics** holds the topic tree and Suggestions (proposed topics, keywords from reviewers' corrections, topics to confirm, documents without a topic). See [KNOWLEDGE_STUDIO.md](KNOWLEDGE_STUDIO.md) and [DOCUMENT_LIFECYCLE.md](DOCUMENT_LIFECYCLE.md) |

## Concepts (one meaning each)

| Concept | Is | Isn't | Backend today |
| --- | --- | --- | --- |
| Source | Where content comes from: a connector source (Confluence, SharePoint, Google Drive, GitHub, website) or an upload | A place people browse | `ingestion_sources`, `external_resources` |
| Resource | One canonical document with metadata. It lives in exactly one collection. | A copy per view | `items` (`item_type=document`) |
| Collection | The governed home: ownership and the access boundary. Managed in Manage › Knowledge Studio → Collections | A place people navigate to read: readers see it as a Browse filter | `items` (`item_type=collection`, root) with role assignments |
| Space | The context people work in (team, project, office; the Campus template adds course and research group). Resources link to many spaces. | An access grant; it only surfaces resources members can already read | Prototype only (Spaces module) |
| Topic | The workspace's taxonomy: domain → topic, each known by its name (its ID is internal, never shown) with signals the assistant classifies by (keywords, synonyms, rules, examples, guidance); readers browse the same topics as pills. Workspace admins manage it in Knowledge Studio → Topics ([DOCUMENT_LIFECYCLE.md](DOCUMENT_LIFECYCLE.md#topics)) | Free-form tags, or a second "category" list beside topics | Proposed: `items.metadata.topics` + a taxonomy table with `keywords`, `synonyms` |
| Saved view | A stored Browse query, kept in Browse's Views menu | A copy of results | Proposed: per-user preference |
| Trust | Verification (by whom, when, next review) + freshness (changed at source) | Index status | Proposed: `items.metadata.verification`; *outdated* already exists (`processed_version`) |

A document's **type** is its file class, derived from the file (`items.item_type`: PDF, Word, Presentation, Spreadsheet, Markdown, HTML, Plain text, Data, Image, Audio, Video, Archive, Other). It is never a business category ("Policy", "Procedure"…), never edited and never suggested by the assistant; what a document is about is carried by its topics.

## Information architecture

```text
Home (/home, core) ─── Ask box with your role's starters · Getting started / Jump back in · Picked for you (with why) ·
                       Explore by domain  (see HOME.md)
Knowledge (sidebar row = Browse; sub-rows Saved · My files while in Knowledge, no tab bar):
├── Browse (/knowledge) ─ the organization's knowledge: topic pills (domains, then a domain's topics) · one bar above
│                      the results: a compact search field, then inline filters Type · Updated · Trust · Owner ·
│                      More filters (Space · Source · Collection · Language), Views (saved views) · sort · layout at its end · removable chips and Ask AI in the
│                      results header · document grid (or list)
│                      card or row → document preview → Open full document (Reader)
│                      a collection is a filter (kb=); a locked one → Request access; "Some collections aren't shared with you" → dialog
└── Saved · My files (/knowledge/library?tab=saved|files) ─ own top-row title each   (Recent and My contributions are under Your work in the sidebar)
Document preview ───── shared modal from every document row, card and citation: Content View (extracted blocks, cited ones highlighted) · Content | Original toggle · Open full document (⋯ Ask · Download)
Reader (/doc/:id) ──── Content View with an outline of the headings · Content | Original toggle · click-to-edit title for editors · Ask | About | Related rail (closed by default; ?ask=1 opens Ask) · Save · Use in… (submissions: preview banner, no Ask)
Manage › Knowledge Studio (/studio) ─ sidebar sub-rows Documents (All · Processing · Review) · Collections · Topics (All · Suggestions) · Sources  (see KNOWLEDGE_STUDIO.md)
     └── Collection (/studio/collections/:id) ─ click-to-edit name and description (owners) · Contents (folders and documents, each folder's click-to-edit name and description; folders with their own access) · Access (owners) · Sources (Add source) · what's in review · Access requests · ⋯ Archive collection (owners)
```

All routes and their purposes are listed in [SCREEN_INVENTORY.md](SCREEN_INVENTORY.md).

## Browse: content first

People come to Knowledge to find and use information, not to manage files. So most of the page is documents, recognisable without opening them; everything else stays out of the way until someone asks for it.

```text
Knowledge · Demo data                                                      [Contribute]   ← top row
[ Search 230 documents                                        ✕  ✦ Ask AI ]   ← Ask AI only with a query
(All) (Engineering & Architecture) (Data Platform…) (Banking Operations) …   ← topic pills
   (All Engineering) (Architecture decisions 20) (APIs 14) …                 ← only when a domain is chosen
[Type ▾] [Updated ▾] [Trust ▾] [Owner ▾] [More filters ▾]   [Views ▾]       ← each filter is a popover with counts
230 documents  [Type: PDF ×]  Clear all      [✦ Ask about these] [Sort ▾] [▦ ☰]
┌ preview ┐ ┌ preview ┐ ┌ preview ┐   three cards a row on desktop, one on phones
└ title, what it's for, type · topic, ✓ ┘ …
```

**Decisions.**
- **No permanent filter rail and no permanent preview panel.** Together they took about half the width. Topic is the one dimension people browse by, so it stays visible as pills. The most used facets (Type, Updated, Trust, Owner) are inline buttons, each opening a popover of checkboxes with live counts that stays open while you tick; the rest sit under *More filters* and appear only when they can still narrow the set. Selected filters show as removable chips beside the result count; *Clear all* clears the topic too. Phones get one *Filters* bottom sheet.
- **Saved views are a menu, not part of the filter form.** *Views* opens a saved view, saves the current one (*Save this view* — saved at once under a name made from the search and filters, with that name open for editing in the results heading) and deletes the active one (Undo). On a saved view the results heading is its name, click-to-edit to rename it (Undo) — no Rename or Save dialog, and the name shows once, not again on the Views button.
- **Search and Ask stay separate.** Search is a compact field at the start of the filter bar — one more way to narrow the same results, at the filter buttons' height and a fixed width, so typing never reflows the filters (it fills the bar beside Filters on phones). Typing always searches documents. *Ask AI* sits in the results header once there is a query and turns it into a cited conversation over these results (without a query, filtered results offer *Ask about these* there). One AI entry point at a time.
- **Browse is the workspace's public knowledge, nothing else.** It lists only documents in shared collections that are published and finished processing. An upload goes to My files — the member's private scope — and never appears here; to share it, the member contributes it, a reviewer approves it (it moves into a collection and is published) and processing runs; only then does it show up in Browse. Unpublished documents and documents still processing (or that failed or can't be processed) stay in Knowledge Studio. The landing shows those documents, newest first. Saved documents live in Saved (recent reads on Home and Your work → Recent); Browse doesn't repeat them. Popular documents stay on Home.
- **A collection is a filter, not a destination.** Readers narrow by collection in More filters (or follow a collection link from a document's details, search or ⌘K). Filtering to a collection you can't read shows who owns it and *Request access* (or that the request is pending), never an empty list.
- **Grid by default, list for dense scanning.** The table layout was removed: the list already scans densely and the table only repeated it.

**Document card** (`X.res.card`):
- **Cover** shows what the document's first page looks like, from the list's own data (`DocumentFacet.cover`) — a card never reads a document's content. The ingestion worker makes the cover as soon as the content arrives, so unprocessed documents have one too, and makes it again when the current version changes. One fixed 16:9 frame per card (nothing shifts while covers load), one shape per format: **PAGE** (PDF, Word) a portrait paper, top-aligned, fading at the bottom; **SLIDE** (decks) a 16:9 slide; **SHEET** (spreadsheets, CSV) a mini grid with column letters and row numbers; **TEXT** (Markdown, plain text, web pages) a paper with the first lines; **IMAGE** the picture itself, cropped to fill. The image (a small WebP: PDF page 1, the picture, or an Office file's embedded thumbnail) always wins over text; without one, the shape is drawn from the first page's title and lines or the first sheet's cells. While searching, a card without a cover image shows the best-matching excerpt the search returned, words highlighted. No cover (not made yet, or nothing to show, e.g. archives): a tinted tile with its file type. Never a page count. Images load lazily and decode off the main thread.
- **Text**: the title (no file extension; the type badge shows it), one line on what the document is for (its summary; never a generated "Guide in Product Documentation" line), then type · topic (or collection). Topic and collection are left out when every card shares it. Trust appears only when it matters: a quiet ✓ for Verified (the tooltip says who and when), a *Review due* chip; nothing for unverified or personal files.
- **Actions**: the whole card opens the document preview (Enter or Space too); Save and ⋯ appear on hover or keyboard focus (always on touch), and a saved document keeps its bookmark visible.

**Document preview** (`X.preview.open`, shared with every resource row, Home, chat and work citations; every citation arrives through `X.openCitation`): a centered modal (a near-full-screen sheet on phones) that opens in **Content View** (`features/content.js`) — the document's extracted blocks (headings, paragraphs, lists, tables, code, formulas, pictures) drawn from its Structured Document: `GetItemContent` returns a window of `ContentNode`s around the cited block, parsed once per document version. A quiet note above the blocks says what this is: *Extracted content — the layout may differ from the original* ("Nội dung trích xuất — có thể khác bố cục bản gốc"). A citation (`{item, revision, structureVersion, refs, quote, location, pageNumber?}`) is highlighted by its block refs, never by searching the page for its text: the cited blocks wear the evidence tint, the one in focus a stronger tint, scrolled into view. *Show earlier part* / *Show later part* ("Xem phần trước / Xem phần sau") page the window, keeping the reader's place. Header: title, collection · updated, and a trust chip only when Verified or Review due. The **reading bar** names where the citation is (its section, and the page only when the parsed pages are the ones the Original shows) and steps through the cited blocks (*n of m*, document by document, in the order the answer first cites each); a search opens on its best-matching block (*Best match for "q"*). At the bar's end sits the **Content | Original** toggle ("Bản gốc"): the Original is the native rendering below, fetched only when chosen, never the default. Only a PDF's Original (its pages are the parsed ones) marks the cited quote on its page; other formats say *Not marked in the original*. Footer: ⋯ (*Ask about this document* — processed documents only — and *Download*) and **Open full document** (the Reader at the same block, content version and view). No Save, editing or sharing — the row it came from already offers those.

**Reader** (`/doc/:id?anchor&v&sv&q&from&view&ask`): the same Content View fills the page, with an **outline** of the document's headings on the left (`GetItemContent` view OUTLINE, shown from three headings; the heading holding what's in focus is marked; picking one brings it to the top). The cited blocks are highlighted — `?anchor` (a block ref, at the revision `?v` and content version `?sv` the citation was read from), or every block the conversation it came from (`?from`) cites in this document — and the reading bar under the title steps through them in document order (*n / m*) and clears them. A search (`?q`) marks its words in the blocks shown. *Show earlier part* / *Show later part* page a larger window. The **Content | Original** toggle sits in the header; `?view=original` shows Bản gốc with its viewer bar (page, zoom). Ask answers in the side panel cite their blocks: a marker highlights that block in the document beside it.

**Content View states** — the same in the preview and the Reader. A citation already carries its quote and location, so the preview shows the quote at once and keeps it above every state: the claim can be checked even when the blocks can't be shown.
- **Loading**: a skeleton of blocks while the window arrives (under the quote in the preview); a document fetched before opens directly.
- **Not processed** (`CONTENT_NOT_PROCESSED`): *Not processed yet* — its content can be read here once it's processed; *View the original* opens Bản gốc now (editors also get *Process* in the Reader).
- **Content version unavailable** (`CONTENT_VERSION_UNAVAILABLE`): the document was processed again after it was cited — *The cited content version is no longer available* ("Phiên bản nội dung được trích dẫn không còn"); *Read the current version* (from the start, no highlight: the refs belonged to the old version) or *View the original*. A ref that isn't in its version (`INVALID_ARGUMENT`) offers *Read from the start*.
- **Permission denied**: a document that isn't shared with you shows only the cited quote and *Request access* (when its collection is locked); the Reader shows its no-access page.
- **Unsupported** (`UNSUPPORTED`): *This file type can't be shown as content* — *View the original*, or *Download* to open it in its own app.

**The Original — opening fast, and always.** *Bản gốc* shows the document's own file, processed or not: processing only adds its content, search, Ask and citations, and a quiet note above the Original says when it hasn't happened yet (or failed), with *Process* for editors. The preview engine prepares one of six representations for every supported file when its content arrives — PDF pages (PDFs, and Word, slides, OpenDocument, RTF, web pages and e-mail converted to their printed pages), a picture, a table (spreadsheets and CSV), text (Markdown rendered, code monospaced), a media player, or a ZIP file's entry list — so the Original looks the same whatever the format; a file opened the moment it was uploaded may show *Preparing the preview…* for a few seconds; anything else offers *Download*. The preview and the Reader show the cover the list already had as the first page at once — its image, else its text in the format's shape — with the next page a sized blank, while the file loads; the real pages replace it when they arrive (a document opened before is cached and opens directly). PDF pages are lazy: only pages within one screen of the view are drawn, one page at a time, the rest are blanks of their exact size, so a long document scrolls with bounded memory and the scrollbar and *Page n of N* stay right.

**States.** Loading shows the search, pills and card skeletons. No results offers *Clear search*, *Clear filters* and *Ask AI*. Long titles clamp to two lines with the full name as a tooltip. A document without a summary or cover still gets a typed tile and its type. When some collections are locked, *Some collections aren't shared with you* opens a dialog listing them with *Request access*; their documents never appear.

**Prototype data.** Northwind's product documentation (`d-prod-3`…`d-prod-14`) has authored text and summaries so its cards differ the way real documents do; the other generated documents use templates, so some covers look alike. Each document's Structured Document (blocks with refs, its chunks and outline) is mocked from that text by `X.docModel` (`documents.js`); quotes the seed data cites are part of their documents' text, so every citation resolves to real blocks. A cover image is mocked by drawing the first page's own HTML small; PDFs, pictures and every other deck have one, Word files and workbooks don't.

## Journeys

1. **Engineer — find, read, ask, keep.** Home → *How do I get production access?* → cited answer → a citation opens the preview in Content View at the cited block; or search "production access" → Browse with the Access Control Policy → preview → *Open full document* → Reader → *Ask* → the cited blocks highlight in the document → *Save* → it shows in Knowledge → Saved.
2. **Engineer — explore by dimension.** Home → topic card *Banking Operations* → Browse filtered by that domain → Type *PDF* → *Views* → *Save this view* → type its name in the results heading → Enter.
3. **Engineer — read with AI beside the decision.** The Reader on *ADR-031 — Idempotency keys for payment APIs* → ask about retries → cited answer → *Related* shows ADR-027 → *Use in… Draft*.
4. **Lead — share with a space.** Link a runbook from another collection to a space → it appears in that space's materials for members who can read it; access is unchanged.
5. **Lead — look after a collection.** Manage › Knowledge Studio → Collections → *Payments Platform* (the card shows its access request) → Access: approve the request, share with a group as Viewer → Sources → Settings. *Review N* in the collection's alert opens its submissions in Knowledge Studio → Documents → Review; the collection's ⋯ *Open in Documents* lists all its documents in Documents → All.
6. **Analyst — find a definition.** Browse → Topic *Metrics & definitions* → *Metric definitions — Active customers* → preview → *Ask about this document* → the Reader's Ask panel → ask what counts as active.
7. **Admin — keep knowledge healthy and visible.** Name the map's levels in Settings › Workspace setup. Overview → Knowledge health → a metric opens its view in Documents or Topics. *Topics → Suggestions*: confirm or move a first sync's topic groups, tag documents the assistant gave no topic, and accept topics the assistant proposed (e.g. *Open banking*); an accepted topic appears in Browse and Edit details at once. *Documents → All → Quality → Re-verification due* (expired or never verified): verify or ask the owner. *Documents → Processing*: documents changed at the source are fixed with *Process the update*. *Quality → Missing details*: add an owner or summary. *Quality → Possible duplicates*: compare, keep the newer and archive the other: saved, recent, space materials, shortcuts and conversation references move to the kept document; Undo restores the archived duplicate only, the references stay where they moved.
8. **Northwind member.** Same screens without spaces: Home's continue section has no Up next, Browse by People/Sales/Product topics; Legal Contracts stays locked — *Some collections aren't shared with you* → Request access.

## Rules

- **Authorization first.** Every listing, count, facet, search, related list and AI answer is computed from `readableResources()`/`catalogPool()` (Browse: `sharedPool()`, the same minus My files). Locked collections appear only as collections, never as resource titles. People who join a public workspace are ordinary members: they read what all members read (collections with general access All members), nothing more.
- **One identity.** Views, saved lists, space materials and topics reference `doc.id`. Merging a duplicate moves its references to the kept document and archives the duplicate; the duplicate gets no badge, state or redirect.
- **Trust over pipeline.** Readers see verification and freshness. Editors also see index status where they can fix it.
- **Demo data is labelled.** Demo workspaces (Finx) have `ws.demo`. The *Demo data* chip sits in the Knowledge header, the Reader and Knowledge Studio. No Finx record claims to be real policy; a Finx "Verified" means verified inside the demo.
- **Reusable.** Nothing checks for a specific workspace. Spaces appear as a facet and as context only when the Spaces module is on. Topics and sources come from data and types from the file and registries (`RESOURCE_KINDS`, `D.topics`, `APPS`).

## Backend alignment and open decisions

The prototype doesn't change `backend/docs_design`. These need backend design before they can ship:

1. **Topics and verification:** extend `items.metadata` (topics, verification `{by, at, due}`, summary, language) or add a taxonomy table. Topics are the workspace-managed taxonomy, named by display name (IDs internal), with `keywords[]`, `synonyms[]`, `rules[]`, `examples[]` and `guidance` (as prototyped); import, export and re-classification are listed in [DOCUMENT_LIFECYCLE.md](DOCUMENT_LIFECYCLE.md#backend-alignment-and-open-decisions).
2. **Resource ↔ space links:** depend on Spaces becoming a backend concept.
3. **Saved resources, recent reads and saved views:** per-user state, which needs a home (preferences store or tables).
4. **Search facets:** `POST /api/v1/documents/search` needs facet counts and filters for type, topic, owner, source, trust, updated and language.
