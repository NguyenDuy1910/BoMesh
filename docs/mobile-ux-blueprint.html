BoMesh Mobile UX architecture and interaction blueprint
Design proposal · before implementation

Product direction

Keep the whole product. Reduce the visible choices.

The mobile app carries every current web destination without turning the phone into a compressed admin console.

1Three top-level destinations

Ask, Library, and Manage. New chat, search, upload, and filters remain actions inside their owning screen.

2One primary action per screen

Related actions collapse into a labelled sheet. Rare, destructive, and row-specific actions move to overflow or detail.

3Control planes stay separate

Workspace and Platform administration share the Manage tab, but a visible mode switch keeps their scope and permissions distinct.

Not shown
No admin or processing controls in the chat surface
  • 48dp touch targets, 8dp minimum separation, safe-area-aware fixed bars.
  • Bottom navigation contains destinations only — never commands.
  • Back preserves list position, filters, selected tab, and unfinished input.
  • Permissions remove inaccessible admin destinations; resource ACLs govern row actions.
  • Every status uses text and shape, not colour alone.
  • Unavailable web capabilities remain explicit, never fake or no-op.
